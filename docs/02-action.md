# 2. 行動控制：動手前擋什麼、動手後怎麼確認

工具回報「成功」只代表呼叫沒出錯，不代表世界真的變成你要的樣子。這一類規則在動作的前後各放一道關卡。

---

## A1 前置檢查（Preflight）

**規則**：不可逆、會影響外部的動作（部署、刪除、寄信、付款）之前，先確認身分、環境和目標。條件不符就停下，不要猜。

**實際案例**
- 猜歌搶答的部署腳本會先檢查目前登入的 Cloudflare 帳號，必須是指定的帳號才部署，避免部署到錯誤帳號。

**怎麼落地**：[preflight_deploy.py](../hooks/preflight_deploy.py) 是 Claude Code 的 `PreToolUse` hook。Agent 要執行 `wrangler deploy` 時，hook 先跑 `wrangler whoami`，帳號不符就回傳 exit code 2 擋下，並把原因告訴 Agent。

---

## A2 寫入後讀回

**規則**：寫檔、改設定、上傳之後，重新讀一次，確認內容真的落地。

**實際案例**
- 揪團日曆：透過遠端工具寫入使用者電腦上的檔案，工具回報成功，檔案其實沒改。之後規定寫完一定讀回，尤其是部署前。
- 猜歌搶答：每次部署後，讀線上 API 的回應和頁面內容，確認跑的是新版本，而不是只看部署指令有沒有報錯。

**怎麼落地**：[verify_write.py](../hooks/verify_write.py) 是 `PostToolUse` hook。每次 `Write`／`Edit` 之後讀回檔案比對，對不上就通知 Agent「不要直接回報完成」。

---

## A3 前後狀態比對

**規則**：操作會改變某個狀態時，操作前讀一次、操作後再讀一次，確認狀態真的改變了。

**為什麼**：有些操作是「切換」，重複執行反而會還原；有些操作會靜默失敗。只看操作後的狀態，分不出是「這次改成功」還是「本來就是這樣」。

**實際案例**
- 用瀏覽器自動化把地點存進 Google Maps 清單：點擊前後各檢查一次清單項目的 `aria-checked`，確認從未勾選變成已勾選。按鈕在第一次儲存後文字會從「儲存」變成「已儲存」，所以判斷要同時接受兩種狀態。

---

## A4 先界定範圍

**規則**：開工前先列出「已經完成的」與「這次要排除的」，交給 Agent 或子 Agent 時明確寫進指令。

**實際案例**
- 請 Exa agent 找新的資安漏洞時，先列出已經寫過的 BIND、PHP、eMudhra 三個主題要求排除，並用 `outputSchema` 固定回傳欄位（CVE、CVSS、揭露日期、來源）。第二輪再限定時間範圍，並排除第一輪已找到的項目。

**怎麼落地**：派工的提示詞固定包含三段：目標、已排除、輸出格式。

---

## A5 留下可追溯的痕跡

**規則**：每次執行都留下不會被下一次覆蓋的紀錄，而且執行完要自己結束，不要卡住等人。

**實際案例**
- Windows 上用 `.bat` 部署：原本最後有 `pause`，視窗卡住後，新的雙擊沒反應，也看不到是哪次失敗。改成 log 寫到不重複的檔名（`logs\deploy-%RANDOM%.txt`），逾時自動關閉。
- 用任務清單記錄每一步的狀態，使用者離開再回來，也看得到做到哪裡。
