# 4. 學習反思：踩過的坑怎麼不再踩

Agent 每次對話都從零開始。沒寫下來的經驗，下次就會重踩一次。

---

## L1 踩坑立刻沉澱

**規則**：遇到「工具行為跟預期不同」的情況，當下就寫進專案的 `CLAUDE.md`「已知陷阱」區塊，寫成下次可以照做的規則，而不是事件紀錄。

好的寫法：`遠端寫檔後一定讀回確認；曾發生回報成功但檔案未更新`
不好的寫法：`10/13 部署失敗了`

**實際案例**（這些都已經整理進 [CLAUDE.md 範本](../templates/CLAUDE.md)）
- 遠端寫檔工具可能回報成功但沒寫入，寫完要讀回。
- 瀏覽器自動化：導航後先截圖一次，頁面才會完整渲染，之後再跑 JavaScript。
- Claude Docs：更新前要先讀取文件拿到正確的區塊 ID，用建立時的骨架 ID 可能改錯地方。
- Cloudflare Workers：`assets.run_worker_first` 只列 API 路由；手動加 `/host` 路由反而出錯，因為靜態資源本來就會處理。

---

## L2 獨立審查

**規則**：高風險的成果（部署、對外發表的文章、會影響決策的分析）交付前，交給一個沒參與製作的審查者，只給它成果與原始資料，不給它製作過程和你的結論。

**為什麼**：自己檢查自己，會帶著製作時的假設去看，同樣的盲點會再錯一次。把結論一起交給審查者，它也容易只是附和。

**怎麼落地**：[reviewer.md](../agents/reviewer.md) 是一個 Claude Code 子 agent。它被要求：
- 每個發現都要附證據（檔案位置、來源）
- 沒問題就說沒問題，不湊數
- 標明每個發現是「確認」還是「疑似」

---

## L3 主動更正

**規則**：發現自己先前說錯，直接說哪裡錯、改成什麼，不要悄悄換掉。

**實際案例**
- 整理時間軸時，原本寫兩個事件「隔天」發生，換算成台北時間後發現其實是「同一天，相隔約 10 小時」，直接更正。
- 使用者追問「這個說法有研究支持嗎」時，承認其中一個說法沒有可靠的研究支持，另一個的證據則有正有反。

**為什麼**：使用者如果發現 Agent 會悄悄改口，就不再相信它任何一句話。明說的更正，反而提高可信度。
